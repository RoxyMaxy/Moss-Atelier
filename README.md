# Moss Atelier

![CI](https://github.com/lonewolfnyx/moss-atelier/actions/workflows/ci.yml/badge.svg)

> **"Describe the person. Get gifts worth giving, and ways to make them."**

Moss Atelier is a quiet, offline-first gift discovery workshop built for the **Hacktoberfest Open-Source AI Challenge (Week 3: "Slow and Steady")**. Its purpose is to reward laziness: no endless scrolling through commercial e-commerce catalogues, no comparing dozens of sponsored products, and no hunting across video platforms for craft instructions. The application handles the search, ranking, and craft adaptation locally and presents a curated, grounded selection.

---

## 1. What It Does

When given a brief description of a recipient (who they are, the occasion, a budget in euros, and up to three passion traits like "coffee", "gardening", "quiet"), Moss Atelier provides:
- **BUY (3 to 5 Curated Gifts)**: Deterministically ranked recommendations grounded in an open catalogue. Every gift includes title, price, tags, and a validated reason. The model is strictly prevented from inventing prices, products, or links.
- **MAKE (2 Practical DIY Ideas)**: Handcrafted project guides with interactive materials checklists, numbered steps ($\le 6$), difficulty ratings (1 to 3), estimated time, and automatic safety disclaimers for hazardous tools (knife, heat, iron, glue gun, solder, bleach, battery).
- **REMEMBER (Local Gift History)**: Local IndexedDB records of past gifts given. When searching for the same recipient, previously given gifts are automatically filtered out, and the UI displays an exclusion count. If a different recipient is entered, the session reinitializes cleanly without cross-contaminating history; returning to an earlier recipient restores their history unharmed.
- **Interactive Pixel Sloth**: A custom $64 \times 64$ pixel sprite rendered in code that breathes during idle periods, remains attentive while searching, dozes into a nap after 30 seconds of inactivity, and rests still when `prefers-reduced-motion` is enabled.

---

## 2. The Open Core (Offline by Design)

The core intelligence of Moss Atelier runs completely on open-source, open-weight components:
- **Local Language Model**: Open-weight **Gemma 3 1B Instruct (`gemma-3-1b-it`)** served locally by Ollama at `http://127.0.0.1:11434/api/chat` (model `gemma3:1b`).
- **Local Embeddings (planned, not yet used by search)**: `nomic-embed-text` through Ollama. Current matching is keyword and synonym based (`js/match.js`).
- **Local Hybrid Search**: PostgreSQL with `pgvector` (`vector(384)`, cosine distance, HNSW index) and full-text search combined with **Reciprocal Rank Fusion ($k = 60$)**.
- **Deterministic Scoring**: Transparent, auditable algorithm:
  $$\text{Score} = 0.40 \times \text{Trait Relevance} + 0.30 \times \text{Occasion Match} + 0.30 \times \text{Budget Fit}$$
  with a strict $+10\%$ maximum budget cutoff.
- **Zero-Dependency Demo Mode**: If local database or inference runtimes are stopped, Moss Atelier seamlessly switches to its bundled CC0 open catalogue (`catalog/catalog.json`) and fallback ideas, ensuring the application never breaks.

## 3. Architecture

```
[ Browser Client (Vanilla HTML/CSS/ES Modules) ]
  │
  ├─ IndexedDB ("moss-atelier") : Local gift history, persistent DIY checklists
  ├─ Canvas (64x64)              : State-driven Sloth sprite (idle, search, dozing)
  ├─ Sentry Agent Tracer         : Privacy-safe spans (retrieve, rank, rationale, diy)
  │
  ▼ HTTP Fetch (Localhost only)
[ Node.js Proxy Server (server/proxy.mjs) ]  <-- node --env-file=.env
  │
  ├─ GET  /healthz        : Status, readiness booleans, zero leaked credentials
  ├─ POST /api/retrieve   : PostgreSQL + pgvector (HNSW) OR in-memory RRF (k=60)
  ├─ POST /api/search     : SerpApi (Google Shopping & YouTube) with 24h TTL cache
  │
  ├──► Local Ollama (Chat)          : http://127.0.0.1:11434 (gemma3:1b)
  ├──► Keyword and synonym matching : js/match.js (no model call)
  └──► PostgreSQL + pgvector        : DATABASE_URL (catalog_items table)
```

## 4. Modes of Operation

1. **OFFLINE (Default)**:
   - All retrieval and scoring execute on local data (`catalog/catalog.json` or PostgreSQL).
   - Explanations generated by local Gemma via Ollama, or deterministic template fallbacks when Ollama is not running. The UI and `/healthz` report which one answered.
   - Zero outbound internet requests.
2. **LIVE (Hosted / With Keys)**:
   - Gemma 26B (`gemma-4-26b-a4b-it`) via Gemini API server-side proxy.
   - SerpApi for Google Shopping and YouTube tutorial discovery with 24-hour memory caching.
   - All API keys reside strictly on the server and never touch the browser.
3. **DEMO**:
   - Zero-dependency demonstration mode displaying curated items from `demo/catalog.json` with a visible DEMO badge.

## 5. Configuration Variables

Environment variables are stored in `.env` (never committed) and read via `node --env-file=.env`:

| Variable | Environment | Purpose |
| :--- | :--- | :--- |
| `DATABASE_URL` | Server | PostgreSQL connection string with pgvector extension |
| `GEMINI_API_KEY` | Server (Secret) | Key for hosted Gemma models (never sent to client) |
| `GEMINI_MODEL` | Server | Model identifier (e.g. `gemma-4-26b-a4b-it`) |
| `SERPAPI_KEY` | Server (Secret) | Key for live Google Shopping & YouTube search |
| `SERPAPI_CACHE_HOURS` | Server | TTL for upstream query cache (default: `24`) |
| `SENTRY_DSN` | Server / Client | Sentry project DSN for error and agent tracing |
| `PORT` | Server | HTTP port (default: `3000`) |

Public configuration is written to `js/config.js` via `npm run build:config`. Secrets are strictly omitted.

## 6. How to Run

### Prerequisites
- Node.js v20.x or later.
- (Optional for vector index) PostgreSQL 16+ with `pgvector` extension.
- Ollama running `gemma3:1b` (chat) and `nomic-embed-text` (embeddings) on `:11434`.

### Setup & Launch
```bash
# Clone the repository
git clone https://github.com/lonewolfnyx/moss-atelier.git
cd moss-atelier

# Verify tests pass
npm test

# Generate public client config
npm run build:config

# Start the local server
npm start
```
Visit `http://127.0.0.1:3000` in your browser.

## 7. Understanding the Offline Test

> [!IMPORTANT]
> **What "Offline" Means**: Moss Atelier is an offline-first architecture that runs entirely on your local machine using local Node.js processes, local database storage, and local model inference (`127.0.0.1`).
>
> If you toggle the Chrome / Firefox DevTools Network setting to **"Offline"**, the browser artificially severs all network sockets—including requests to `http://127.0.0.1:3000`. Under this synthetic test:
> - The **Service Worker (`sw.js`)** will intercept the page navigation and serve the cached application shell, stylesheets, fonts, and sloth animations from cache storage.
> - The application UI will seamlessly display demonstration data and allow full local exploration.
> - True offline operation means disconnecting your machine from external Wi-Fi / Ethernet: Moss Atelier will continue to operate with local models and PostgreSQL without needing an active internet connection.

## 9. Known Limitations

1. **System Memory**: On machines with less than 1,000 MB free RAM, `build-index.mjs` automatically halts to prevent out-of-memory crashes, operating via fast in-memory RRF instead.
2. **Catalogue Scope**: The local curated catalogue currently contains 126 handcrafted items (106 gifts, 20 DIY projects).
3. **Price Fluctuations**: Commercial prices change over time; offline prices reflect curated benchmark estimates.
4. **Model Context**: Local Gemma 1B operates within a 2048-token context window; gift candidate lists are kept compact ($\le 8$ items).
